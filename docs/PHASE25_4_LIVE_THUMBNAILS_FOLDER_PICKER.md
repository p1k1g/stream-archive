# Phase 25.4 — LIVE 방송 썸네일 및 채널 폴더 선택

상태: 구현 및 자동 검증 중. 실제 Windows / SOOP / CHZZK 수동 QA는 별도 확인이 필요합니다.

## LIVE 이미지 표시

- 오프라인: SOOP / CHZZK 플랫폼 로고를 40×40 논리 픽셀 영역에 비율 유지하여 표시합니다. 채널 프로필 이미지는 사용하지 않습니다.
- 방송 감지 후: 기존 LIVE 조회에서 얻은 방송 식별자와 공개 썸네일 정보를 사용합니다. 120×67.5 논리 픽셀의 16:9 영역에 전체 이미지를 표시하며 중앙 자르기를 하지 않습니다.
- SOOP은 현재 player가 사용하는 방송별 `https://liveimg.sooplive.com/m/{bno}` 경로를 사용합니다. CHZZK는 기존 `live-detail`의 `liveImageUrl`을 사용하고 `{type}`을 `270`으로 치환합니다. 해당 값이 없으면 같은 응답의 `defaultThumbnailImageUrl`을 사용합니다.
- CHZZK 썸네일 URL이 없거나 이미지 다운로드 / 형식 검증에 실패하면 플랫폼 로고를 표시합니다. 인증 쿠키, 비밀번호, Worker API key를 이미지 요청에 전달하지 않습니다.
- 기존 방송 제목, 상태, 녹화 크기, 저장 경로 및 채널별 동작은 유지합니다. 채널 관리에 LIVE 대시보드를 복제하지 않습니다.

## 캐시 및 새로고침

- 방송별 첫 이미지 조회 결과를 유지합니다. 자동 상태 polling이 같은 방송의 이미지를 반복 다운로드하지 않습니다.
- LIVE의 `새로고침`은 현재 방송 이미지를 다시 요청합니다. 실패하면 직전 성공 이미지를 유지하고, 성공 이미지가 없으면 로고를 표시합니다.
- 방송 종료, 채널 제거 / 사용 중지, 방송 감시 중지, 방송 식별자 변경 시 기존 이미지와 UI 참조를 해제합니다.
- LIVE 녹화 파일의 종료 처리가 끝나면 해당 방송 캐시를 삭제합니다. 녹화 종료 기록 후 메모리상의 완료 식별자와 revision을 갱신하므로, 같은 방송이 polling 사이에 녹화 재개되어도 삭제를 놓치지 않습니다.
- 녹화만 중지되고 방송이 계속되는 경우 자동 재조회는 막고 로고를 표시합니다. 수동 `새로고침` 또는 새 방송 식별자에서 조회를 허용합니다.
- 삭제 / 새로고침 이전의 늦은 응답은 generation 검사로 폐기합니다. 자동 조회 실패도 같은 방송에서 반복 재시도하지 않습니다.
- 다른 탭을 보고 있어도 이미지 캐시나 요청이 남아 있으면 기존 메모리 상태 snapshot을 확인해 완료 / 종료를 반영합니다. 다른 탭을 보거나 실제 창이 시스템 트레이로 숨겨진 상태에서는 새 이미지 다운로드를 요청하지 않습니다. 창을 다시 표시하고 LIVE 탭을 보면 아직 조회하지 않은 방송의 이미지를 요청합니다.
- 디스크 캐시는 만들지 않습니다. 최대 128개 활성 방송, 동시 요청 최대 2개, HTTP body 최대 8 MiB, 원본 최대 4096×4096 / decode 할당 최대 64 MiB, 결과 최대 480×270입니다. HTTPS provider CDN allowlist와 redirect 거부, 요청 및 전체 작업 timeout을 적용합니다.

## 채널 저장 폴더

- 기존 경로 직접 입력과 `기본 경로 사용` 동작을 유지합니다.
- `폴더 선택`은 기존 Windows native directory picker를 사용하고 현재 입력 경로에서 시작합니다.
- 취소하면 기존 편집 내용과 dirty 상태를 유지합니다. 선택 후에도 `채널 저장`을 눌러야 SQLite에 저장됩니다.
- picker 응답의 채널 목록이 현재 draft와 다르면 다른 채널에 경로가 반영되지 않도록 응답을 무시합니다.

## 유지하는 계약

GUI는 `StreamArchiveCore`를 통해서만 provider 이미지를 요청합니다. 추가 LIVE 조회 API, SQLite schema / migration, INI/TXT mirror, UI 직접 HTTP / SQLite / 프로세스 제어는 도입하지 않습니다. 녹화 프로세스의 소유권과 종료 경로, VOD / Queue / History / Backup, renderer / 폰트, 제품 버전 `1.0.0`은 유지합니다. thumbnail metadata와 완료 revision은 런타임 메모리에만 보관합니다.

## 자동 검증

캐시의 최초 조회 유지, 수동 새로고침 실패 시 보존, 완료 후 삭제, 같은 방송의 두 번째 완료, 새 방송 조회, 늦은 응답 폐기, 요청 / 캐시 상한, null metadata, provider URL 제한, 이미지 손상 / 과대 응답 / format 제한 / 비율 유지, picker draft 불일치를 테스트합니다. 기존 fmt / check / unit tests / clippy와 Windows / Linux / macOS package 및 RuntimeContracts 검증을 유지합니다.

## 수동 QA — 아직 완료하지 않음

- [ ] Windows 기본 크기 / 최소 크기 / 125%·150%·200% DPI에서 LIVE 이미지와 버튼 확인
- [ ] SOOP / CHZZK 오프라인 로고가 잘리지 않고 표시됨
- [ ] 실제 SOOP / CHZZK 방송 시작 후 썸네일 및 metadata 표시
- [ ] 썸네일 URL이 없는 CHZZK 방송에서 로고 fallback
- [ ] 자동 polling 동안 첫 썸네일 유지
- [ ] `새로고침` 성공 시 교체 / 실패 시 기존 이미지 유지
- [ ] 방송 종료 후 로고 복귀와 이미지 참조 해제
- [ ] 다른 탭 / 시스템 트레이 상태에서 녹화 완료 후 기존 이미지 캐시 삭제
- [ ] 녹화 정상 완료 / 일시중지 / 오류 종료 후 캐시 삭제 및 자동 재조회 차단
- [ ] 같은 방송 수동 새로고침 후 재차 녹화 완료 시 캐시 삭제
- [ ] 요청 중 채널 제거 / 감시 중지 / 방송 변경 후 늦은 이미지가 다시 나타나지 않음
- [ ] 채널 폴더 picker의 현재 경로 시작 / 한글·공백 경로 / 취소 / 저장 / 재실행 유지
- [ ] 기본 크기와 최소 크기에서 채널 경로 입력·폴더 선택·이름 조회·삭제 접근 가능
- [ ] 장시간 실행 중 이미지 / handles / threads의 지속 증가 여부 확인

이 문서의 체크되지 않은 항목은 자동 테스트 결과로 완료 처리하지 않습니다. PR merge, tag 생성 및 GitHub Release publication은 사용자가 결정합니다.
